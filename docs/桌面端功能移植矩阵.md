# SpiritScout 网页版到原生桌面端功能移植矩阵

更新时间：2026-11-25
目标分支：`codex/upstream-v022-architecture`
验收平台：Windows 原生 Kotlin Compose + SaltUI
禁止替代：WebView 套壳、仅导航入口、用通用 JSON 编辑器冒充专用业务界面

## 状态定义

| 状态 | 含义 |
| --- | --- |
| 未开始 | 桌面端没有对应入口，或入口存在但没有业务实现 |
| 进行中 | 已有原生页面、控制器或 API 接线，但字段、交互、错误处理或行为测试尚未闭环 |
| 已移植 | 功能与页面已实现，仍需最终端到端验收 |
| 已验证 | 行为级测试或真实 Windows 桌面流程已通过，有可复现证据 |
| 平台等价 | 网页平台专属交互无法逐像素复用，但桌面端已有等价操作和结果 |

`DesktopParityTest` 只证明枚举或入口存在，不证明功能完成。未通过行为测试的项目不得标为“已验证”。

## 当前真实限制

1. 第三方 Provider、OAuth、额度和实时抓包的真实外部结果取决于本机凭据、网络和网卡；产品代码与本地夹具已覆盖。
2. Windows SmartScreen 仍可能显示“发布者未知”；这需要受信任的 Authenticode 证书，不能由 Compose 或 SaltUI 规避。
3. 全量 Python 并行回归在 12 进程下出现临时数据库/密钥目录争用；10 个失败模块已串行复跑并全部通过，其余 411 个模块并行通过。
4. 当前机器 PATH 中没有 Go，最终包使用已通过 `test_traffic_proxy` 的预构建 `spiritscout-traffic-proxy.exe`。
5. 构建物、Wheel、Sdist、ZIP、EXE 和 SHA256 文件均不提交 Git。
