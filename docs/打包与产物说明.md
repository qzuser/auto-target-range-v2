# 打包与产物说明

Windows 发布链统一位于 `packaging/windows/`，最终产物按用途分目录，避免把
桌面版、后端运行时和 Python 包混在一起。

```text
<仓库根>/
├── desktop/                         Kotlin Compose + SaltUI 桌面源码
├── packaging/windows/
│   ├── build-desktop.ps1            唯一完整桌面版入口
│   ├── build-backend-runtime.ps1    Python embeddable 后端运行时
│   └── build-backend-console.ps1    PyInstaller 后端控制台
└── src/                             Python 后端源码

dist/
├── windows/
│   ├── desktop/                     SpiritScout-<版本>-windows-x64.zip
│   └── backend-console/             可选后端 EXE
└── python/                          wheel / sdist

build/
└── backend-runtime/                 可复用的内嵌 Python 运行时
```

## 完整桌面版

先生成 wheel：

```powershell
uv build --wheel --outdir dist\python .
```

再生成完整桌面版：

```powershell
powershell -ExecutionPolicy Bypass -File packaging\windows\build-desktop.ps1
```

最终文件：

```text
dist\windows\desktop\SpiritScout-<版本>-windows-x64.zip
```

解压后双击 `SpiritScout.exe`。包内包含 Compose Desktop 原生界面、精简 JRE、
Python 后端运行时和配置模板，不依赖 WebView2、Java 或系统 Python。

`-RuntimeDir` 可复用已经验证过的后端运行时；不再产生 portable/native 两套叫法。

## 后端兼容包

- `build-backend-runtime.ps1` 生成 `build/backend-runtime/`，供桌面打包和排障复用。
- `build-backend-console.ps1` 生成 `dist/windows/backend-console/SpiritScout-<版本>-windows-x64-backend.exe`；
  该兼容包只在本地显式构建，不进入正式桌面发布链。
- 后端兼容包使用 `SpiritScout-<版本>-windows-x64-backend.zip` 命名，不冒充完整桌面版。

Python 嵌入包会依次尝试华为云、npmmirror、清华镜像和 Python 官方源；依赖安装优先使用
清华 PyPI，镜像失败时自动回退官方源。

## 验证

```powershell
$env:JAVA_HOME = '<你的 JDK 21 安装目录>'   # 需要 JDK 21
.\desktop\gradlew.bat -p .\desktop test --rerun-tasks

& .\packaging\windows\build-backend-runtime.ps1 `
  -OutDir .\build\backend-runtime
```

完整桌面包还应从空目录解压启动，确认窗口标题、后端就绪、Skill 列表和关闭窗口后的
Python 进程清理。Windows SmartScreen 的“发布者未知”提示需要 Authenticode 证书签名
才会消失。
