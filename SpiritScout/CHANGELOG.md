# 更新日志

项目采用 `主版本.次版本.修订号`。当前版本为 **0.35.2**，版本唯一来源是
`src/spiritscout/__init__.py`；包构建、命令行、控制台及 MCP 握手共用该值。

**历史版本说明**：0.1.0 是仓库早期已有的代码版本；0.2.0—0.11.1 根据现有
Git 历史与日期日志回溯整理，用于标识功能演进，**并非当时已发布的版本或 Git 标签**。
不把每次提交视为一次发布，不改写 Git 历史，也不倒填发布标签。历史条目描述当时的
行为，部分规则后来已有调整，请以当前代码和最新条目为准。

版本递增和发布记录规则见 [贡献指南](CONTRIBUTING.md#版本管理)。

## [0.35.2] - 2026-11-02

设管理员密码不再挑字符数：想用几位就用几位，设完能在终端里看见那一次。

### 修复

- **去掉密码长度限制**：`--set-admin-password` 原来有一条「至少 8 个字符」的硬性
  检查，`web/auth.py::validate_credentials` 另有一条「不超过 1024 个字符」。现在两
  条都删掉，只留「空密码 = 不设密码」：一位口令与整句话都收，设密与登录两侧一致
  （`/api/auth/login` 同步去掉长度截断，否则设了长口令反而登不进来）。
  scrypt 的开销由 `N/r/p` 决定，与口令长度无关，删掉限制不改变哈希成本。
- **空密码不再当成「设了个空密码」**：交互终端回车两次、或 `--password-stdin` 喂空行
  时跳过写库并提示「等于不开启登录」，而不是留一个空口令账号——空口令等于把控制台
  敞开，比不设密码更糟。

### 新增

- **设完在前台显示一次**：交互终端里写完哈希后打印一行
  `本次设置的密码（只在这里显示一次，之后不再显示）：<明文>`，方便当场记下来；
  之后重启、`/api/auth/status`、日志与界面都不再显示它，库里始终只有 scrypt 哈希。
  `--password-stdin`（启动脚本、CI、管道）不回显，避免明文跟着 stdout 进日志。

## [0.35.0] - 2026-11-02

经验库只留一本账：提炼出来的东西一定进库，重复的东西一定不进库。

### 新增

- **入库前查相似，重复的直接取消**：`ExperienceStore.add` 先查完全同文
  （`experience.duplicate`），再与库里最近 2000 条**有效**条目算编辑相似度
  （复用 `knowledge/merge.py` 的 `similarity`：去空白标点后 `difflib` 比例）。
  达到 `experience.duplicate_threshold`（默认 **0.95**）就取消这条结果、只留审计
  `experience.near_duplicate`（带命中条目与分数），其余照常入库。阈值可调，设 1.0
  即退化成「只挡完全同文」。0.95 比二次提炼合并用的 0.85 更严——合并有原件托底
  且可还原，入库是新增，宁可少存。
- **提炼如实交代跳过了几条**：提炼结果多一个 `duplicates`，`result` 在「一条都没
  进库」时区分 `empty`（模型没给出）与 `duplicate`（给的都是重复的）。会话页「经验」
  页签的提示与「提炼记录」都按它说话：`提炼完成，新增 1 条经验，跳过 2 条与库里
  高度重复的`。

### 修复

- **自动提炼写错了库**：`_open_workspace` 与 `resume_pending_distills` 按**会话**
  工作区算路径，条目落进 `sessions/<id>/experience.db`，而「经验库」页与开工召回
  读的是共享库——于是「提炼成功、库里没有」。现在统一由
  `knowledge/experience.py::shared_db_path(cfg)` 给出落点（`experience.root` 为空
  则跟随基础工作区），自动提炼、手动提炼、重启补跑、经验页、会话页、删会话前并库
  全都用它；升级时启动阶段的 `absorb_session_dbs` 会把旧版本散落的会话库并回共享库
  （幂等，同文与高度相似自动跳过）。

## [0.34.0] - 2026-11-02

模型选择从「全局一份」变成「全局一份 + 每个会话可以自己挑」，并且优先级链在
运行期定时重读——改完设置不用重开会话，更不用重启进程。

### 新增

- **会话级模型选择**：会话页状态标签里多了一个模型下拉。选定后只有这一个会话
  改用它（灵枢车道 + 没在编队页指派的子 Agent），「自动 · 跟随全局优先级」则
  回到「模型」页排的顺序。落在 `Session.model`（`meta.json` 随会话持久化，
  重启后仍在），接口 `POST /api/sessions/{id}/model`；网关侧由
  `ModelGateway.set_session_model` 承接。
- **改动即时生效**：Web 端传的是 `lambda: session.model`，网关每次调用现取——
  运行中的会话中途改选择，下一批调用就改道，不必等本轮结束。
- **优先级链定时重读**：`ModelRegistry` 带一个优先级来源回调，运行期按
  `gateway.priority_refresh_seconds`（默认 30 秒，`5~3600`）重读
  `agent_models.yaml` 的 naming 链。改顺序只影响后续调用，不给每次调用加一次
  文件读；读失败/格式坏沿用上一份排序，不让路由倒在这里。
- **预览口径一致**：新增 `ModelGateway.resolve_model`，界面提示与实际调用算的
  是同一个模型；`AgentBoundGateway` 也实现了它，绑定不会再被预览绕过。

### 修复

- **编队表半截时不再拖垮启动**：`agent_models.yaml` 保存到一半（YAML 语法错）
  原先会把 `yaml.ParserError` 抛到网关构造处，整条调用链起不来；现在
  `_read_doc` 统一包成 `SpiritScoutError`，调用方按「读不到优先级」退回旧行为。
- **会话选的模型被删了不再报错**：选定条目从注册表消失后，调用退回优先级链并
  记一条 `model.override_missing` 审计，而不是每次调用都抛「未注册的模型」。

### 取舍（写在代码里，也写在这）

- 优先级顺序是 **显式绑定 > 会话选择 > 设置页优先级链**；但主 Agent 车道是
  **会话选择 > 编队页给灵枢的指派**（用户当场选择优先于全局配置）。编队页给
  具体子 Agent 的指派仍然优先于会话选择——那是逐角色的定点配置。
- 会话可以选到没配密钥的模型（页面照实列出），失败时按现有提示去「模型」页
  补 Key，或把选择清掉。

### 测试

- `tests/test_model_selection.py`（14 项）：优先级链改完即重读、重读间隔内不
  重读、坏文件沿用旧链、链上已删条目被忽略、会话选择压过优先级链、显式绑定
  仍最优先、callable 现取、模型被删后回落、主 Agent 车道 vs 子 Agent 车道的
  优先级、`set_model` 落盘并能在新 manager 里读回、未知模型拒绝、清空回全局。
- `tests/test_session_model_api.py`（5 项）：选中返回当前值并出现在会话列表、
  空值撤销、未知模型 422、未知会话 404、多余字段 422。
- `tests/test_session_model.js`：自动/已选/已下线三种选项形态、chip 的 `on`
  状态与说明文案、POST 请求体与本地状态回写、模型列表只拉一次、接口挂了降级
  成只剩「自动」。
- 全量：1178 项 unittest（失败仍是环境基线那 18+2、跳过 15），ruff 全绿，
  29 个 JS 测试全过。

## [0.33.0] - 2026-11-02

经验库新增二次提炼（极相似条目合并压缩），并把「删会话不删经验」钉成硬约定。

### 新增

- **二次提炼**：「经验」页的「二次提炼」面板列出**整组两两相似度都 ≥ 85%** 的条目
  （归一化后的编辑相似度，中文同义改写也认得出来），每组带合并预览，点一下才合并；
  也可以勾选任意几条强行合，服务端会复检并拒绝不够相似的组合（400 并说明最低相似度）。
  实现：`knowledge/merge.py`（`similarity` / `compose` / `build_groups`，完整连接聚类，
  链式 A≈B≈C 但 A≁C 时不成立）+ `knowledge/experience.py` 的
  `merge_candidates` / `merge_insights` / `restore_merge`，接口
  `GET /api/experience/merge/candidates`、`POST /api/experience/merge`、
  `POST /api/experience/merge/restore`。
- **合并是确定性的，不调模型**：取信息量最大的那条当底稿，其余条目里底稿没有的句子
  按「另：…」并入——压缩的是重复表述，不是事实，避免润色时丢掉差异细节。
- **原件不删、可还原**：被合并的条目只标记 `merged_into`（库结构新增
  `merged_into` / `merged_from` 两列，老库启动自动补列）。默认列表与开工召回不再
  展示已合并项，`include_merged=true` 或页面「显示已合并」可看到灰掉的原文并「还原」；
  删掉一条合并结果时，它的原件自动解封，不会永远挂在隐身上。

### 修复

- **删会话不再有丢经验的风险**：经验本来就在共享库里，`SessionManager.delete` 只删

  `experience.db` 并回共享库，避免「会话一删，旧经验随目录消失」。来源会话不存在时，

  `api_key=''` 的条目——换成新加的渠道立刻变成 litellm 的
  `Missing credentials. Please pass an api_key`。现在启动时统一
  `vault.apply_keys()`，`SessionManager` 构造时再兜一次，任何一条拿到清单的路径
  都能直接调用。
- **本机端点补占位密钥**：LM Studio / Ollama 这类 `127.0.0.1` 端点本不校验密钥，
  但 litellm 见到 `openai/` 前缀就要求非空 `api_key`，同样报 `Missing credentials`。
  `gateway/credentials.py` 现在给本机端点（`localhost`/`127.0.0.0/8`/`*.local`）
  自动填 `sk-local`；远端端点仍必须自带密钥。
- **没密钥的渠道不再挡在链首**：路由排序把「远端且无密钥」的条目挪到最后，只有
  全都不可用时才按原顺序给出目标，让报错里带着可查的模型名。
- **报错说人话**：全链失败且底层是 `Missing credentials` 时追加一句「这条渠道没有
  可用密钥：去「模型」页给对应供应商填 API Key，或把它从优先级链里移掉（本机端点
  会自动用占位密钥）」，不再只把 litellm 原文甩出来。

### 测试

- `tests/test_model_priority.py` 增 5 项：本机端点拿占位密钥、远端无密钥判为不可用、
  无密钥渠道被挪到可用渠道之后、全都不可用时仍按优先级给目标、全链失败信息包含

## [0.18.1] - 2026-10-30

- **终端窗口不再只说第一句话**。原来 `python -m spiritscout` 打出「灵枢 Web 控制台:
  http://…」就进 `uvicorn.run()` 阻塞，此后窗口一言不发。可那行提示打出时监听还没
  建起来——照着点过去可能连不上；跑起来之后跑了多久、手上几个会话、吃了多少内存，
  也全得另开任务管理器看。

  现在换成可控的 `uvicorn.Server`，另起一条守护线程：等端口**真能收下 TCP 连接**
  再喊一次就绪，之后按间隔报状态。

  ```
  灵枢 Web 控制台: http://127.0.0.1:8010  (管理员登录已启用，并发上限 4，Ctrl+C 停止)

  [就绪] 浏览器可以打开了: http://127.0.0.1:8010
         每 60 秒报一次状态；Ctrl+C 停止

  [状态] 已运行 01:00 · 会话 2（运行中 0） · 内存 244 MB
  ```

  几个取舍：

  - 探活用真实 TCP 连接，不猜固定秒数——首次启动要建库、预热模型，多久说不准，
    猜短了提示是假的，猜长了白等。
  - 守护线程里取数失败只丢那一项，不把服务带崩；`psutil` 不是核心依赖，没装就
    少报内存，其余照打。
  - 90 秒还连不上会打一行提示，不让窗口哑着。
  - 主线程仍归 `server.run()`——信号处理只能在主线程装，挪进守护线程会直接抛
    `signal only works in main thread`，Ctrl+C 就废了。

- 修复工具参数超长导致整链失败：模型单次工具调用（如长 python 脚本）生成中途被截断时，litellm 在协议层直接抛错、工具环无从回灌——现在把「截断、未执行」作为事实回灌重发一次，缩短参数由模型自行决定（此前 glm-5.3-flash 写长脚本必触发全链失败）
- CTF 页面观察保住题面文案：HTML 摘要段序改为文案优先（可见文本前移到链接清单之前、超长保头保尾），观察帽 3000→4000、回放帽同步放宽——此前接口清单挤占预算，页面提示最先被截掉，模型看到的"页面"只剩接口直接暴力打；解题提示词补「先读懂页面再动手」通用认知
- 新增「经验提炼」页（资产收集下方）：经验全量可检索/按标签过滤、来源会话回链、右侧提炼记录逐场留痕（成功/落空/失败原因原样可见）

- 经验召回改为「[标签] 洞察（适用：场景；来源：目标）」注入灵枢与子 Agent，便于判断同场景参考
